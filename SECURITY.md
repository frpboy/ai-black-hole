# Security Policy

## Supported versions

This project is pre-release software. Until the first stable release, only the latest default-branch state is considered for security fixes. No service-level commitment is provided.

## Reporting a vulnerability

Please do not publish exploitable vulnerability details in a public issue. If GitHub's **Report a vulnerability** private reporting feature is enabled for this repository, use it. Do not publish exploit details in a public issue. The repository owner should enable private vulnerability reporting in repository security settings. Include the affected version or commit, package and configuration, reproducible steps, impact and suggested mitigation.

We will acknowledge reports as soon as reasonably possible and coordinate a fix and disclosure with the reporter.

## Safe use

Only test systems you own or have explicit permission to assess. Do not access, modify, exfiltrate or disrupt third-party data or services. Do not use decoy mechanisms to create resource exhaustion or external costs.

Never include live credentials, tokens, customer data or private keys in issues, pull requests, examples or test fixtures.
